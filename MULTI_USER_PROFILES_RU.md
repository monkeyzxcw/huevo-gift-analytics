# Многопользовательские профили AMNYAM

## Модель приложения

- **Рыночные данные общие.** Каталог, «База», «Ниже рынка», «Дешёвые», аналитика, детали подарков и публичные агрегаты берутся из одного общего снимка. Авторизация не скрывает вкладки и не создаёт отдельную копию рынка для каждого пользователя.
- **Настройки персональные.** У каждого логина отдельная запись в Cloudflare D1: избранные lot ID, целевые цены, уже сработавшие цели, сохранённые фильтры, звук, тема оформления, маскот, анимации и праздничная тема.
- **Гостевой режим остаётся доступен.** Без входа приложение работает как раньше, а локальные настройки остаются в браузере. Они не синхронизируются между устройствами.
- При создании первого аккаунта текущие локальные избранное, цели, фильтры и настройки браузера отправляются в создаваемый профиль. При обычном входе серверный профиль заменяет состояние гостя, без смешивания данных двух пользователей.

## Аккаунты и безопасность

Регистрация выполняется прямо в окне «Войти в профиль». Логин: 3–24 латинских символа, цифры, точка, дефис или подчёркивание. Пароль: 12–128 символов. Пароль от Huevo использовать нельзя.

Worker хранит PBKDF2-SHA-256 хеш пароля с индивидуальной случайной солью, а не исходный пароль. Сессия — случайный токен в HttpOnly, Secure, SameSite=Lax cookie; в D1 сохраняется только SHA-256 хеш токена. Мутации профиля принимаются только с точного same-origin Origin. Попытки регистрации и входа ограничиваются по времени и хешированному ключу источника.

**Почта, подтверждение адреса, восстановление/сброс забытого пароля и удаление аккаунта пока не подключены.** Пользователю необходимо самостоятельно сохранить пароль в менеджере паролей. Не используйте один пароль с Huevo или другими сервисами.

## API аккаунтов

| Метод | Путь | Назначение |
|---|---|---|
| POST | /api/auth/register | Создать аккаунт и первую сессию |
| POST | /api/auth/login | Войти и загрузить свой профиль |
| POST | /api/auth/logout | Завершить текущую сессию |
| GET | /api/me | Получить текущего пользователя и его профиль |
| PUT | /api/me/profile | Сохранить только профиль текущей сессии |

Каждый ответ профиля проверяется и очищается по списку разрешённых полей. Клиент не может запросить или изменить профиль другого user ID: пользователь определяется только по HttpOnly session cookie. Рыночный data.json не содержит пользовательские избранное или настройки.

## Развёртывание

1. В wrangler.jsonc уже задана существующая D1 huevo-live-data, binding DB.
2. Миграция migrations/0003_multi_user_profiles.sql создаёт таблицы user_accounts, user_sessions, user_profiles и auth_rate_limits.
3. Workflow .github/workflows/cloudflare-static.yml применяет все новые D1 migrations при деплое, если у Cloudflare API Token есть D1: Edit.
4. После применения миграции регистрация и вход доступны сразу. Дополнительные secrets для аккаунтов не требуются. У существующего `CLOUDFLARE_API_TOKEN` должно быть право `D1: Edit` на базу `huevo-live-data`.

Проверка: GET /api/me без cookie должен вернуть authenticated: false и profiles_ready: true. Если profiles_ready: false, проверь результат Apply D1 migrations в GitHub Actions и право D1: Edit у Cloudflare token.

## Ограничения уведомлений

Звуковая настройка синхронизируется как предпочтение аккаунта, но проигрывается локально в открытой вкладке браузера. Разрешение на браузерные уведомления хранится самим браузером и не переносится между устройствами. Это пока не Web Push: вкладка должна оставаться открытой и получать обновления рынка.
