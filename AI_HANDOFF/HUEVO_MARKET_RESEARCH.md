# Исследование HTML huEVO: подтверждённые факты

Это факты из HTML/Network материалов, присланных владельцем. Это не официальная документация API. Не делай выводов о скрытом API без дополнительного подтверждения.

## Каталог подарков
Запрос из DevTools:
- GET https://huevo.su/market/gifts?page=3
- Status 200 OK
- Content-Type text/html; charset=utf-8
- Response — HTML, не JSON.
- Заголовки X-Huevo-Frag: 1 и X-Huevo-Pjax: 1 похожи на fragment/PJAX navigation, но не доказывают, что ответ содержит только фрагмент.
- Vary включает Accept-Encoding, X-Huevo-Frag, X-Huevo-Pjax, Cookie.

Вывод: отдельный JSON API каталога пока не найден; HTML parsing — подтверждённый вариант. В карточках можно извлекать lot ID, название, serial, тираж, редкость, цену, статус и изображение. Пример, упомянутый ранее: lot 29025, forbidden.vlc, #203 из 222, 55 000 монэток. Пример не гарантированно актуален.

## История сделок
Canonical URL: https://huevo.su/market/history. Переданный HTML содержит:
- table class mk-table;
- колонки Лот, Цена, Продавец, Покупатель, Дата;
- ссылки лота /market/lot/<id>;
- фильтры /market/history?kind=gift, /market/history?kind=username и /market/history?mine=1;
- указано «Страница 1 из 652» и ссылка на /market/history?page=2;
- примеры: lot 28831 «Жидкость Brusko #4», 444444 монэток, продавец «рё⠀», покупатель Andrew, отображаемое время «01:22». В других строках есть 700000 и несколько продаж по 1 монэтке, поэтому нужно использовать медиану/квантили и осторожно относиться к выбросам.

В доступном фрагменте столбец даты отображает часы/минуты, но календарная дата/год или Unix timestamp не подтверждены. Изучи атрибуты и соседние страницы; не придумывай даты.

## Сессия
Пользователь отправил Request Headers целиком, включая Cookie сессионных идентификаторов. Секретные значения намеренно не записаны в handoff. Считай сессию раскрытой и порекомендуй инвалидировать/обновить её. Никогда не проси повторно cookies. Для диагностики достаточно URL без секретных параметров, метод/status/content-type и небольшой очищенный пример ответа.

## Реализация в экспериментальной ветке `experiment/market-intelligence-lab` (PR #31, не вливать без решения владельца)

- Добавлен best-effort parser индивидуальной страницы `/market/lot/<id>`: whitelist model/backdrop/symbol/pattern/rarity/serial/supply/collection, безопасная Huevo image URL; seller/owner data не копируются.
- После полного прохода каталога проверяется максимум 8 uncached lot pages за запуск; кэш — 60 дней; пауза между запросами не менее 3 секунд. Любой block останавливает detail pass; сбой enrichment не отменяет валидный полный каталог.
- Публичные детали прикрепляются к соответствующему lot через `gift_details`; если карточка не раскрывает известные поля, сохраняется пустой набор атрибутов и статус, без догадок.
- История сделок собирается из первых 3 страниц локально. Публично выходят только агрегаты после порога 20 известных цен; группировка по нормализованному названию, так как sale parser не извлекает характеристики конкретного экземпляра.
- Профиль продажи включает count, median, P25/P75, min/max. По дням график строится только на явном timezone-aware `sold_at`; время вида `01:22` само по себе не является датой.
- Текущие объявления отделены от завершённых продаж. Если продаж по названию ≥5 — reference median sales; иначе предварительная медиана только после robust outlier fence / проверки split clusters. Неустойчивая выборка не порождает сигнал.
- История объявления удерживается 30 дней; polling использует backoff; браузерный alert sound opt-in.
- Детали HTML остаются best-effort до проверки на реальной авторизованной карточке. Если разметка Huevo не совпадёт с whitelist, интерфейс честно покажет «характеристики не распознаны» и не подставит догадки.

## Остаточные ограничения / проверка перед merge
1. Реальный authenticated HTML карточки подарка ещё нужно проверить на одном-двух лотах: текущие fixtures синтетические, а selectors defensive.
2. История продаж в `history_parser.py` может отображать лишь HH:MM; если нет явного timestamp, временная шкала не доступна. Не вычислять дату по crawl time.
3. Sale history сейчас агрегируется по названию подарка; до появления идентификатора характеристик в строке сделки не утверждать, что продажи сгруппированы по модели/фону/символу конкретного экземпляра.
4. Регулярно следить за размером локальной `history.db` и лимитами Huevo; не сканировать все 652 страницы и не обходить блокировки.
5. PR #31 is experimental. Do not merge or deploy without explicit owner approval.
