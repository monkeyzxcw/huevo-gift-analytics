# Huevo Gift Analytics

Панель аналитики **текущих предложений** маркета подарков Huevo: каталог, выгодные предложения, динамика медианы, история цен, поддержка автора через платежи huEVO Apps. Приложение ничего не обходит: нет прокси, смены IP, подмены заголовков и повторов после отказа.

> Важно: цены в панели — цены объявлений, а не завершённых сделок. Huevo не публикует историю продаж, поэтому «лучший лот» считается по ушедшим с рынка лотам (вероятно проданы или сняты) либо по медиане активных предложений, и основа всегда показана в карточке.

## Архитектура

| Файл | Назначение |
|---|---|
| `app.py` | HTTP-слой FastAPI: эндпоинты, авторизация, лимиты, заголовки безопасности |
| `storage.py` | SQLite: схема и миграции (`PRAGMA user_version`), upsert, снимки, каталог с пагинацией, бэкап |
| `lot_parser.py` | HTML → строки лотов; проверка данных от браузерного сборщика |
| `crawler.py` | цикл серверного сбора (Selenium через внедряемый `browser`), без повторов после блокировки |
| `cookies.py` | разбор экспорта cookies (JSON / Netscape), белый список хостов Huevo |
| `huevo_probe.py` | классификация страницы, реальный HTTP-статус и `Retry-After` из журнала Chrome |
| `analytics.py` | чистая математика: медиана, квартили, группы сопоставимых лотов, выгодные предложения |
| `support.py` | платежи huEVO Apps: подпись запуска, callback, идемпотентность |
| `security.py` | Content-Security-Policy |
| `static/` | интерфейс (`index.html`, `app.css`, `app.js`) и `browser_collector.js` |
| `tests/` | unittest (Python) и Playwright (`tests/e2e`, фикстуры страниц Huevo) |

## Источники данных и честность статуса

1. **Браузерный сбор (рекомендуется).** Скрипт запускается в DevTools уже авторизованной вкладки `huevo.su`, читает страницы вашей сессией и шлёт лоты на панель с `INGEST_TOKEN`. Cookies никуда не уходят. Адрес панели жёстко ограничен (`*.onrender.com` или `localhost`), токен нигде не сохраняется.
2. **Серверный Selenium** (только если заданы `HUEVO_COOKIES_JSON` / `HUEVO_COOKIES`). Реальный HTTP-статус берётся из сетевого журнала Chrome (`status_source: network`); если журнал недоступен, блокировка определяется по тексту страницы (`inferred`), и панель так и пишет.

Полный проход — только если на странице после первой нет новых лотов. Лоты, не встреченные при полном проходе, помечаются неактивными; при неполном проходе (ошибка, блокировка, лимит страниц, подозрительно малая выборка — менее 50% прежних активных лотов) активность и снимки рынка **не меняются**.

## Что делать при 418 / 403 / 429 / сетевых ошибках

| Симптом | Значение | Действие |
|---|---|---|
| 403 / 418 / 429 | Huevo ограничил доступ (реальный статус из сети или признак на странице) | Сбор остановлен; пауза не короче `CRAWL_BLOCK_COOLDOWN_HOURS` и не короче `Retry-After`. Пауза хранится в БД и переживает перезапуск. Подождите; используйте браузерный сбор из своей авторизованной вкладки |
| страница входа | сессия или домен cookies не подходят | перелогиньтесь в браузере и используйте браузерный сбор |
| 5xx | временная проблема источника | повторить позже |
| `dns` / `tls` / `timeout` / `connect` | сеть узла или источник недоступен | проверить «Проверку доступа к Huevo» во вкладке «Сборщик» |
| нет карточек | изменилась разметка или не отрисовался JS | сверить селекторы в `lot_parser.py`, обновить фикстуры |

Проверка доступа: вкладка «Сборщик» → «Проверить доступ к Huevo» (один запрос к `/` и `/market/gifts?page=1`, не чаще раза в `DIAG_COOLDOWN_SECONDS`, без cookies и тела страницы в ответе).

## Запуск целиком в Docker Compose (VPS / свой сервер)

В репозитории есть `Dockerfile` и `docker-compose.yml`: контейнер запускает веб-панель, API и планировщик серверного сбора. SQLite хранится в именованном Docker volume `huevo-gift-analytics-data`, поэтому данные переживают пересоздание/перезапуск контейнера.

1. Установите Docker Engine с Compose plugin на сервере и склонируйте репозиторий.
2. Создайте конфигурацию: `cp .env.example .env`.
3. В `.env` замените `INGEST_TOKEN` на длинный случайный секрет. Для автоматического серверного сбора задайте `HUEVO_COOKIES_JSON` как JSON-массив cookies **одной строкой**. Не коммитьте `.env` и не отправляйте cookies в чат.
4. Запустите: `docker compose up -d --build`.
5. Проверьте: `docker compose ps`, `docker compose logs -f huevo-gift-analytics`, затем откройте `http://IP-СЕРВЕРА:8000`. Для публичного доступа настройте HTTPS через домен и reverse proxy; не выставляйте административные секреты в URL.
6. Обновление: `git pull && docker compose up -d --build`.

Важное про сессию: Docker сохраняет конфигурацию из `.env` и базу между перезапусками, но **не может заставить Huevo сохранять действительность сессии**. Если Huevo отзовёт/просрочит cookies или потребует повторный вход, потребуется обновить `HUEVO_COOKIES_JSON` в `.env` и пересоздать контейнер командой `docker compose up -d`. Если cookies не заданы, панель запустится, но автоматический серверный сбор не начнётся. Не используйте `docker compose down -v`: флаг `-v` удалит постоянную базу.

Для локального теста на компьютере команды те же; панель будет доступна по `http://localhost:8000`.

## Развёртывание на Render

1. Подключите репозиторий (Docker, ветка `main`). `render.yaml` создаёт `INGEST_TOKEN` автоматически.
2. В **Render → Environment** задайте секреты (только там): при необходимости `HUEVO_COOKIES_JSON`, для оплаты `HUEVO_CLIENT_ID` и `HUEVO_CLIENT_SECRET`.
3. Откройте панель → «Сборщик» → скачайте сборщик, откройте маркет в авторизованной вкладке, вставьте код в консоль и введите токен в окне запроса.

**Постоянное хранение.** На бесплатном плане Render диск временный: `huevo.db` теряется при деплое и перезапуске (панель покажет предупреждение). Для долговременной истории подключите persistent disk (платная опция, автоматически не включается) и задайте `HUEVO_DB=/var/data/huevo.db`. Копия базы: `curl -H "Authorization: Bearer $INGEST_TOKEN" -o huevo-backup.db https://ВАШ-СЕРВИС.onrender.com/api/backup`. PostgreSQL не реализован.

## Переменные окружения

`INGEST_TOKEN`, `HUEVO_BASE_URL` (`https://huevo.su` или `https://huevo.departament.site`), `HUEVO_COOKIES_JSON` / `HUEVO_COOKIES`, `HUEVO_DB`, `CRAWL_DELAY`, `MAX_PAGES`, `CRAWL_BLOCK_COOLDOWN_HOURS`, `AUTO_REFRESH_HOURS`, `DIAG_COOLDOWN_SECONDS`, `LOG_LEVEL`, `HUEVO_CLIENT_ID`, `HUEVO_CLIENT_SECRET`. Шаблон — `.env.example`. Секреты не коммитятся и не пишутся в логи.

## API

Публичные (GET): `/health`, `/api/status`, `/api/diagnostics`, `/api/catalog` (`q, sort, status, rarity, min_price, max_price, limit≤200, offset`), `/api/facets`, `/api/lots/by-ids`, `/api/lots` (совместимость), `/api/stats`, `/api/highlights`, `/api/deals`, `/api/drops`, `/api/analytics/summary`, `/api/analytics/snapshots`, `/api/analytics/price-history`, `/api/history/{lot_id}`, `/api/support/config|stats|status/{id}`.

Защищены `Authorization: Bearer <INGEST_TOKEN>` (токен в query-строке не принимается; 10 неверных попыток за 5 минут → 429): `POST /api/ingest`, `POST /api/ingest/complete`, `POST /api/crawl`, `POST /api/diagnose-huevo`, `GET /api/backup`.

Платежи: `POST /api/support/intent` (подпись запуска `hu_*`), `POST /api/support/callback` (подпись `X-Huevo-Signature` по сырому телу). Финальный статус платежа не перезаписывается; повторные callback безопасны.

## Безопасность

Размеры запросов ограничены (ingest — 2 МБ и 1000 лотов), `lot_id` — только цифры, SQL — параметризованный, `LIKE` экранируется, сортировка — из белого списка, весь пользовательский текст в интерфейсе экранируется, CSP запрещает inline-скрипты и стили, CSV нейтрализует формулы, CORS только для хостов Huevo, внешние ссылки — `rel="noopener noreferrer"`.

## Тесты

```bash
pip install -r requirements.txt httpx
python -m unittest discover -s tests -v      # парсер, БД, аналитика, краулер, cookies, зонд, платежи, API
npm install && npx playwright install chromium
npm run check && npm run test:e2e            # сборщик и интерфейс (фикстуры, без обращений к реальным сайтам)
```

CI (`.github/workflows/ci.yml`): Python-тесты, браузерные тесты, сборка и запуск Docker-образа.

## Ограничения

- Разметка парсера (`.mk-gcard`, `.mk-gtitle`, `.mk-price`…) выведена из прежних наблюдений и фикстур; на живом Huevo из этой среды не проверялась.
- «Последний лот» — лот, замеченный сборщиком последним; время выставления сайт не отдаёт.
- Оплата работает только внутри huEVO (нужны подписанные параметры запуска); в боевом режиме не проверена.
- История и аналитика копятся по мере проходов; пока снимков меньше двух, панель пишет «Недостаточно данных».
