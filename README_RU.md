# Huevo Gift Analytics — готовый проект

Панель аналитики рынка подарков с FastAPI, SQLite, историей изменения цены и серверным планировщиком обновлений. Проект не использует выдуманные котировки: до первого успешного сбора база будет пустой.

## Состав проекта

- `app.py` — API, база данных, история цен и безопасная диагностика.
- `static/index.html` — панель статистики, поиск, сортировка, история лотов, диагностика подключения и экспорт загруженного каталога в CSV.
- `static/browser_collector.js` — сборщик для уже авторизованного браузера; его можно скачать прямо из панели.
- `static/obsidian.css` — оформление интерфейса Obsidian Gold.
- `static/obsidian.js` — живые панели покрытия данных, распределения цен, структуры редкости и отклонений цен у лотов с одинаковым названием. Запрашивает данные у API, не содержит демонстрационных котировок.
- Планировщик в `app.py` — запускает серверный обход только если задана `HUEVO_COOKIES_JSON`; без серверной сессии приложение не делает бесполезные попытки и ждёт импорта из авторизованного браузера. Интервал задаётся `AUTO_REFRESH_HOURS` (по умолчанию 2 часа).
- `requirements.txt` — зависимости Python.
- `Dockerfile` — запуск сервера в контейнере.
- `render.yaml` — настройки автоматического деплоя на Render и генерация `INGEST_TOKEN`.
- `.env.example` — пример переменных окружения для локального запуска.

## Развёртывание на Render

1. Распакуйте архив и загрузите **содержимое** папки `huevo_gift_analytics` в корень GitHub-репозитория `huevo-gift-analytics`.
2. Сделайте commit в ветку `main`. На Render создайте/обновите сервис через Blueprint по `render.yaml` либо оставьте существующий Docker-сервис подключённым к репозиторию.
3. В Render → Environment убедитесь, что задан `INGEST_TOKEN`. Blueprint создаёт случайное значение автоматически. Если переменная отсутствует в существующем сервисе, создайте длинный случайный токен вручную. Не используйте пароль Huevo и не публикуйте токен в GitHub.
4. После деплоя проверьте `https://ВАШ-СЕРВИС.onrender.com/health` и `https://ВАШ-СЕРВИС.onrender.com/api/diagnostics`. Диагностика показывает только наличие настройки, никогда не раскрывая секрет. В самой панели кнопка «Проверить подключение» выводит состояние базы, истории и импортёра; «Экспорт CSV» сохраняет загруженные строки каталога.
5. Откройте панель, скачайте `browser_collector.js`, затем откройте `https://huevo.su/market/gifts` в том же браузере и войдите в аккаунт, если нужно.
6. Нажмите F12 → Console, откройте скачанный JS-файл в редакторе, проверьте код, скопируйте его целиком в консоль и выполните. Если браузер предупреждает о вставке кода, внимательно следуйте его защите и не запускайте код, который не проверили.
7. Введите HTTPS-адрес панели и значение `INGEST_TOKEN` из Environment на Render. Сборщик отправит распознанные лоты, после чего обновите панель.

## Локальный запуск

Требуется Python 3.11+. В терминале из папки проекта выполните:

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
# PowerShell: $env:INGEST_TOKEN = "ваш-длинный-секрет"
# macOS/Linux: export INGEST_TOKEN="ваш-длинный-секрет"
uvicorn app:app --host 127.0.0.1 --port 8000
```

Затем откройте `http://127.0.0.1:8000`.

## Проверки

В репозитории настроен GitHub Actions workflow `.github/workflows/ci.yml`: он запускает регрессионные тесты API и проверяет синтаксис JavaScript панели и браузерного сборщика на каждом push в `main` и для pull request.

## API

- `GET /health` — проверка работоспособности.
- `GET /api/diagnostics` — безопасная диагностика конфигурации и числа записей.
- `GET /api/status` — состояние фонового и планового сборщика.
- `GET /api/stats` — число лотов и статистика цен.
- `GET /api/lots?q=&sort=price&limit=500` — поиск и сортировка.
- `GET /api/history/{lot_id}` — история изменения цены и статуса лота.
- `GET /api/analytics/price-history?days=7&lot_id=...` — дневные агрегаты сохранённых наблюдений цены за период до 90 дней; это история изменений предложений, не завершённых продаж.
- `POST /api/ingest` — защищённый импорт данных от браузерного сборщика через `Authorization: Bearer ...` (старый query-параметр `token` пока поддерживается для совместимости).

## Важные ограничения

- Серверный Selenium-сборщик работает только при явно настроенной `HUEVO_COOKIES_JSON`. Без неё `POST /api/crawl` возвращает понятную ошибку, а планировщик не запускает заведомо нерабочий обход. Основной способ без копирования cookies — `static/browser_collector.js` в уже авторизованном браузере.
- Если серверный сборщик видит страницу ограничения Huevo (403/418/429 или проверку браузера), он прекращает обход и ставит повторные попытки на паузу на число часов из `CRAWL_BLOCK_COOLDOWN_HOURS` (по умолчанию 6). Ручной браузерный сборщик также останавливается при 418/403; для 429 он может ждать только если сервер явно прислал `Retry-After`. Это не снимает блокировку на стороне Huevo.
- Разметка парсера ориентирована на классы `.mk-gcard`, `.mk-gtitle`, `.mk-gserial`, `.mk-gsub`, `.mk-price` / `.mk-gprice` и `.mk-status`. Если Huevo изменит разметку, парсер потребуется обновить.
- Автоматический сбор выполняется на сервере по расписанию; кнопка в панели запускает дополнительную попытку. Интервал задаётся через `AUTO_REFRESH_HOURS`.
- Бесплатный тариф Render обычно не предоставляет постоянный диск. Если для сервиса не подключён persistent disk, SQLite-файл может потеряться при перезапуске или новом деплое. Для долговременной истории нужен постоянный диск или внешняя база данных.
- `client_id` / `client_secret` Huevo не нужны этому способу сбора. Не добавляйте их, cookies или пароль в репозиторий. Не подтверждено, что официальный Huevo API предоставляет каталог маркет-лотов.

## Если `.gitignore` или `.env.example` не видны на GitHub

Оба файла должны лежать в корне репозитория рядом с `app.py`. Точка в начале имени — часть имени файла. В Windows включите **Вид → Показать → Скрытые элементы** и в Проводнике включите отображение расширений. Загружайте содержимое папки проекта, а не ZIP-файл как один файл.

Если используете Git, выполните из корня проекта:

```bash
git add .gitignore .env.example
git add app.py static/ README_RU.md requirements.txt render.yaml Dockerfile
git status --short
git commit -m "Fix project files and dashboard UI"
git push
```

`.env.example` — только шаблон. Настоящий `.env` намеренно исключён из Git через `.gitignore`; не загружайте в репозиторий токены и пароли. Для Render добавьте `INGEST_TOKEN` в **Dashboard → ваш сервис → Environment**. Если `.gitignore` уже отслеживается Git, изменения в нём всё равно будут включены в коммит.
