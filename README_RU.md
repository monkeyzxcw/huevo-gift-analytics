# Huevo Gift Analytics — готовый проект

Панель аналитики рынка подарков с FastAPI, SQLite, историей изменения цены и серверным планировщиком обновлений. Проект не использует выдуманные котировки: до первого успешного сбора база будет пустой.

## Состав проекта

- `app.py` — API, база данных, история цен и безопасная диагностика.
- `static/index.html` — панель статистики, поиск, сортировка, история лотов, диагностика подключения и экспорт загруженного каталога в CSV.
- `static/browser_collector.js` — сборщик для уже авторизованного браузера; его можно скачать прямо из панели.
- `static/obsidian.css` — оформление интерфейса Obsidian Gold.
- `static/obsidian.js` — живые панели покрытия данных, распределения цен, структуры редкости и отклонений цен у лотов с одинаковым названием. Запрашивает данные у API, не содержит демонстрационных котировок.
- Планировщик в `app.py` запускает серверный обход только при заданном экспорте cookies; интервал задаётся `AUTO_REFRESH_HOURS` (по умолчанию 2 часа).
- Домен выбирается через `HUEVO_BASE_URL`: `https://huevo.su` или `https://huevo.departament.site`. Cookies должны быть свежими и экспортированными именно с выбранного домена — cookies одного хоста не переносят авторизацию на другой.
- Поддерживаются JSON-экспорт расширений (включая поле `expirationDate`) через `HUEVO_COOKIES_JSON` и Netscape `cookies.txt` через `HUEVO_COOKIES`. Это альтернативные форматы одного типа данных, а не разные уровни авторизации.
- `requirements.txt` — зависимости Python.
- `Dockerfile` — запуск сервера в контейнере.
- `render.yaml` — настройки автоматического деплоя на Render и генерация `INGEST_TOKEN`.
- `.env.example` — пример переменных окружения для локального запуска.

## Развёртывание на Render

1. Распакуйте архив и загрузите **содержимое** папки `huevo_gift_analytics` в корень GitHub-репозитория `huevo-gift-analytics`.
2. Сделайте commit в ветку `main`. На Render создайте/обновите сервис через Blueprint по `render.yaml` либо оставьте существующий Docker-сервис подключённым к репозиторию.
3. В Render → Environment убедитесь, что задан `INGEST_TOKEN`. Blueprint создаёт случайное значение автоматически. Если переменная отсутствует в существующем сервисе, создайте длинный случайный токен вручную. Не используйте пароль Huevo и не публикуйте токен в GitHub.
5. Для браузерного сбора откройте `https://huevo.su/market/gifts` или `https://huevo.departament.site/market/gifts` в том же браузере, в котором вход уже выполнен. Браузерный сборщик использует текущий домен и не копирует cookies на Render.
6. Нажмите F12 → Console, откройте скачанный JS-файл в редакторе, проверьте код, скопируйте его целиком в консоль и выполните. Если браузер предупреждает о вставке кода, внимательно следуйте его защите и не запускайте код, который не проверили.
7. Введите HTTPS-адрес панели и значение `INGEST_TOKEN` из Environment на Render. Сборщик отправит распознанные лоты, после чего обновите панель.

## Локальный запуск

Требуется Python 3.11+. В терминале из папки проекта выполните:

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
# PowerShell: $env:INGEST_TOKEN = "ваш-длинный-секрет"
# macOS/Linux: export INGEST_TOKEN="ваш-длинный-секрет"
uvicorn app:app --host 127.0.0.1 --port 8000
```

Затем откройте `http://127.0.0.1:8000`.

## Проверки

В репозитории настроен GitHub Actions workflow `.github/workflows/ci.yml`: он запускает регрессионные тесты API и проверяет синтаксис JavaScript панели и браузерного сборщика на каждом push в `main` и для pull request.

## API

- `GET /health` — проверка работоспособности.
- `GET /api/diagnostics` — безопасная диагностика конфигурации и числа записей.
- `GET /api/status` — состояние фонового и планового сборщика.
- `GET /api/stats` — число лотов и статистика цен.
- `GET /api/lots?q=&sort=price&limit=500` — поиск и сортировка.
- `GET /api/history/{lot_id}` — история изменения цены и статуса лота.
- `GET /api/analytics/price-history?days=7&lot_id=...` — дневные агрегаты сохранённых наблюдений цены за период до 90 дней; это история изменений предложений, не завершённых продаж.
- `POST /api/ingest` — защищённый импорт данных от браузерного сборщика через `Authorization: Bearer ...` (старый query-параметр `token` пока поддерживается для совместимости).

## Важные ограничения

- Серверный Selenium-сборщик требует действующую сессию в `HUEVO_COOKIES_JSON` или `HUEVO_COOKIES`. Если Huevo хранит часть авторизации в localStorage или привязывает сессию к браузеру/сетевому адресу, одного экспорта cookies может быть недостаточно; тогда используйте `static/browser_collector.js` внутри уже авторизованной вкладки.
- Если серверный сборщик видит страницу ограничения Huevo (403/418/429 или проверку браузера), он прекращает обход и ставит повторные попытки на паузу на число часов из `CRAWL_BLOCK_COOLDOWN_HOURS` (по умолчанию 6). Ручной браузерный сборщик также останавливается при 418/403; для 429 он может ждать только если сервер явно прислал `Retry-After`. Это не снимает блокировку на стороне Huevo.
- Разметка парсера ориентирована на классы `.mk-gcard`, `.mk-gtitle`, `.mk-gserial`, `.mk-gsub`, `.mk-price` / `.mk-gprice` и `.mk-status`. Если Huevo изменит разметку, парсер потребуется обновить.
- Автоматический сбор выполняется на сервере по расписанию; кнопка в панели запускает дополнительную попытку. Интервал задаётся через `AUTO_REFRESH_HOURS`.
- Бесплатный тариф Render обычно не предоставляет постоянный диск. Если для сервиса не подключён persistent disk, SQLite-файл может потеряться при перезапуске или новом деплое. Для долговременной истории нужен постоянный диск или внешняя база данных.
- `client_id` / `client_secret` Huevo не нужны этому способу сбора. Не добавляйте их, cookies или пароль в репозиторий. Не подтверждено, что официальный Huevo API предоставляет каталог маркет-лотов.

## Если `.gitignore` или `.env.example` не видны на GitHub

Оба файла должны лежать в корне репозитория рядом с `app.py`. Точка в начале имени — часть имени файла. В Windows включите **Вид → Показать → Скрытые элементы** и в Проводнике включите отображение расширений. Загружайте содержимое папки проекта, а не ZIP-файл как один файл.

Если используете Git, выполните из корня проекта:

```bash
git add .gitignore .env.example
git add app.py static/ README_RU.md requirements.txt render.yaml Dockerfile
git status --short
git commit -m "Fix project files and dashboard UI"
git push
```

`.env.example` — только шаблон. Настоящий `.env` намеренно исключён из Git через `.gitignore`; не загружайте в репозиторий токены и пароли. Для Render добавьте `INGEST_TOKEN` в **Dashboard → ваш сервис → Environment**. Если `.gitignore` уже отслеживается Git, изменения в нём всё равно будут включены в коммит.



## Диагностика источника (одна безопасная проверка)

Перед включением автосбора выполните по порядку (токен берите из Render → Environment, в чат его не отправляйте):

1. `GET /health`, затем `GET /api/diagnostics`.
2. `curl -X POST -H "Authorization: Bearer $INGEST_TOKEN" https://ВАШ-СЕРВИС.onrender.com/api/diagnose-huevo` — один раз открывает `/` и `/market/gifts?page=1` и возвращает только: итоговый хост, заголовок, длину страницы, число карточек и вердикт. Cookies и содержимое страницы не возвращаются. Лимит — раз в `DIAG_COOLDOWN_SECONDS` (по умолчанию 300 с); при блокировке повторные запросы не отправляются.

Вердикты: `network_error` (dns/tls/timeout/connect) — сетевая проблема; `blocked` — ограничение со стороны Huevo (защита не обходится); `login` — сессия/домен cookies; `no_cards` — разметка или JS; `ok` — парсер видит карточки.
Если вердикт `blocked` или `login`, используйте браузерный сборщик из уже авторизованной вкладки.

## Данные и перезапуск Render

На бесплатном плане диск временный: `huevo.db` теряется при деплое и перезапуске. Для истории нужен платный план с persistent disk (`HUEVO_DB=/var/data/huevo.db`) или внешняя БД; PostgreSQL пока не реализован.


## Что нового в этой версии

- Прокси/VLESS удалены полностью: сервис ходит напрямую, ничего не обходит. При ограничении (418/403/429) сбор останавливается и ставится пауза `CRAWL_BLOCK_COOLDOWN_HOURS`.
- `POST /api/crawl` и `POST /api/diagnose-huevo` требуют `Authorization: Bearer <INGEST_TOKEN>`; панель спросит токен и держит его только в памяти вкладки.
- Снимки рынка (`market_snapshots`): после каждого полного прохода сохраняются число активных лотов, мин/макс/среднее/медиана. `GET /api/analytics/snapshots?days=30`.
- Лоты, не встреченные при **полном** проходе (дошли до конца каталога), помечаются неактивными. Неполный проход (ошибка, блокировка, лимит `MAX_PAGES`) активность не меняет. Браузерный сборщик в конце вызывает `POST /api/ingest/complete`.
- `GET /api/deals` — лоты ≥15% ниже медианы не менее чем трёх активных предложений с тем же названием. Это подсказка, а не оценка, и не цены завершённых продаж.
- Панель: фильтры по статусу, редкости и цене, постраничный вывод, блок выгодных лотов, график по снимкам рынка, понятная свежесть данных.
- Логи сборщика: URL, хост, заголовок, длина страницы, число карточек, новые/изменённые лоты, время; cookies и токены не логируются.


## Версия 3: вкладки, главные карточки, поддержка автора

**Интерфейс** (`static/index.html`, `app.css`, `app.js`): вкладки Обзор, Каталог, Выгодные, Аналитика, Избранное, Сборщик, Поддержать. Клавиша `/` открывает поиск. Избранное хранится только в браузере.

**Главные карточки**
- «Последний выставленный лот» — `GET /api/highlights`. Сайт не отдаёт время выставления, поэтому берётся лот, замеченный сборщиком последним (при равенстве — с наибольшим ID). Допущение про рост ID не проверено.
- «Лучший лот к рынку» — эталон: медиана последних цен лотов того же названия, ушедших с рынка (минимум 3). Причину ухода сайт не раскрывает, поэтому это «вероятно проданы или сняты», а не подтверждённые сделки. Если таких лотов мало, берётся медиана активных предложений; основа показана в карточке. Реальной истории продаж у проекта нет.
- Также: `GET /api/drops` — лоты, подешевевшие по сохранённой истории.

**Поддержка автора** построена по документации huEVO Apps (https://huevo-docs.lunnaholy.workers.dev/apps/monetization/payments/):
1. В кабинете разработчика huEVO создайте приложение, адрес приложения — адрес панели на Render. В настройках укажите callback `https://ВАШ-СЕРВИС.onrender.com/api/support/callback`.
2. В Render → Environment задайте `HUEVO_CLIENT_ID` и `HUEVO_CLIENT_SECRET` из вкладки «Ключи доступа». Секрет хранится только на сервере.
3. Поток: сервер проверяет подпись параметров запуска `hu_*` (HMAC-SHA256, ключ SHA-256 от секрета) → `POST /payments` (`test=true`, пока `hu_mode=test`) → в браузере `huevo.confirmPayment` → сервер подтверждает итог через `GET /payments/{id}` или подписанный callback (`X-Huevo-Signature`). Результат из браузера ничего не подтверждает; финальный статус не перезаписывается.
4. Кнопка работает только когда панель открыта внутри huEVO как приложение. Вне huEVO аккаунт игрока неизвестен, и панель так и говорит.
Эти запросы идут к официальному API приложений (`https://huevo.su/api/apps/v1`), а не к маркету.

**Парсинг маркета.** Документация описывает API приложений (платежи, кошелёк, пользователи, уведомления, треки) и не содержит методов для маркета, лотов или истории продаж, поэтому сбор по-прежнему идёт через браузерный сборщик или серверный Selenium.
